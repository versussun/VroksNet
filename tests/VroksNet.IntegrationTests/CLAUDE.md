# VroksNet.IntegrationTests

Aspire integration tests: boots the *real* distributed-application graph (`AppHost.cs` as-is — `apiservice`, `webfrontend`, and the RabbitMQ/NATS containers `apiservice` waits on) via `Aspire.Hosting.Testing`, then drives it over the wire. Shared xUnit rules are in `tests/CLAUDE.md`.

- **Black-box only.** This project doesn't reference Domain/Application/Infrastructure — tests talk JSON/HTTP against the real endpoints, not server-side types, so they can't silently pass against an internal shape that doesn't match the actual wire contract.
- **One shared boot per test run, not per test.** Booting the graph starts real containers and takes several seconds; `Fixtures/AppHostFixture.cs` (`IAsyncLifetime`) builds and starts it once, and `Fixtures/AppHostCollection.cs` (`[CollectionDefinition("AppHost")]` + `ICollectionFixture<AppHostFixture>`) shares that one instance across every test class in the `[Collection("AppHost")]` group — which also makes them run sequentially against the same `apiservice` process and its single-writer SQLite queue (see `src/VroksNet.Infrastructure/CLAUDE.md`), so tests must not assume isolated state between each other.
- **Requires a running container runtime** (Docker Desktop or compatible) — `AppHost.cs`'s `apiservice` resource `.WaitFor(rabbitmq).WaitFor(nats)`, so these tests can't boot without one. Skip/don't run this project in an environment with no container runtime available.
- **The database is fresh every run** — `AppHost.cs` doesn't set `ConnectionStrings:VroksNetDb` for `apiservice`, so it gets the in-memory default (see `src/VroksNet.Infrastructure/CLAUDE.md`), not the `vroksnet.db` file a real dev run would also default to. Still use GUID-suffixed values for anything with a unique constraint (e.g. `Connection.Name`) rather than relying on that — it's what makes these tests safe to run repeatedly against a *persisted* database too, if `ConnectionStrings__VroksNetDb` is ever set for a debugging session. Specification imports are naturally safe to repeat either way since `UpsertAsync` replaces by `Title`.
- **Success-path coverage for outbound sends** (`Connection` test, `TestScenario` run over `Http`) points an `Http` connection back at the booted ApiService's own `/health`. Failure-path coverage of the same classes lives in `VroksNet.UnitTests` (no Docker needed).
